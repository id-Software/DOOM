# Quirks: faults of building the source on a 64-bit host

[Back to the register index](../QUIRKS.md).

Every row on this page is a fault of **building this source on a 64-bit (LP64) host**. The code is correct on the original 32-bit target, where `int`, pointers and `long` share one width, so none of these is a behaviour of linuxdoom-1.10 as shipped. **None of them is ever a candidate for a fixes profile** or for a change to the port's behaviour: the owner ruled on 2026-11-21 that they live apart from the quirk tables for that reason. Each row says whether the genuine-engine reference harness (`tools/reference`) is affected and how it copes. The two former exposure unknowns were settled by reading the build source lists and inheritance on 2026-11-22; those are source inspections, not new harness runs.

A fault that is also a quirk on the original target stays in the main tables, with the 64-bit difference as a note: for example the `memset (mousebuttons, ...)` of G_DoLoadLevel (Q-g_game-495: 4 bytes on the 32-bit original, 8 under LP64), the sound-origin read of P_UpdateSpecials (Q-p_spec-1151) and the short-lump read of getsfx (Q-i_sound-230). `state_t`'s `long` fields (info.h) were considered and are not a fault: every value fits 32 bits, so no outcome depends on the width (listed under [Dropped, and why](dropped.md)).
